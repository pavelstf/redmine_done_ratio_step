# Повторен QA тест на Done Ratio Step 1.0.6

## Подготовка

1. Провери ZIP файла със съседния файл `.zip.sha256`: `sha256sum -c redmine_done_ratio_step-1.0.6-qa.zip.sha256`. В PowerShell използвай `Get-FileHash redmine_done_ratio_step-1.0.6-qa.zip -Algorithm SHA256` и сравни резултата.
2. Използвай отделна Redmine QA среда и тестови задачи. Архивирай текущата папка на плъгина, ако има такава. Разархивирай и постави папката `redmine_done_ratio_step` директно под `plugins/`. Обнови JavaScript по процедурата на средата и рестартирай приложението. Няма миграции или допълнителни gem зависимости.
3. Потвърди версия **1.0.6** в **Administration → Plugins**. Отвори **Network** с включено **Disable cache** и провери, че JavaScript от HTTP отговора съвпада с хеша в локалния протокол. При fingerprinted assets провери файла, поискан от браузъра.
4. Запиши точната версия на Redmine, браузъра, темата, активните плъгини и настройките за интервал. Изпълни тестовете на 6.1.2, ако е наличен. Повтори основните сценарии на Redmine 5.x, ако има такава среда.

## Допълнителна регресия

- Провери 0% и 100%, съхранени 15% и запазване на друго поле без смяна на процента.
- В bulk edit първата празна опция трябва да остане избрана. Смени тракер или статус и провери процента след обновяване на формата.
- С включен плъгин провери основните сценарии на тема GCR и с другите плъгини, които променят менюто. Огледай браузърната конзола за грешки.
- Отчети за всеки сценарий **PASS**, **FAIL** или **BLOCKED**. При дефект приложи стъпки, видим резултат и URL на JavaScript файла. За сценарии със запис използвай само тестови задачи.

За връщане възстанови архивираната папка на плъгина и публикуваните JavaScript файлове по процедурата на QA средата, после рестартирай приложението.
